# 简历与面试用材料 · HiPod

> 说明：本项目为 vibecoding 方式开发（代码由 AI 智能体编写，本人负责需求定义、技术选型、真机验收与发布）。
> 下面的表述按此事实写，重点放在**你实际做了什么**；被追问时如实说明即可，不必主动展开。

## 一、一句话版（技能行 / 项目列表）

> **HiPod** — Android 复古点击轮音乐播放器（React Native / Expo）。完成从交互设计、真机验收到签名分发的完整流程：双主题零重建架构、程序化材质贴图、中文像素字体管线、两个 Android config plugin。

## 二、三点式（项目经历条目）

**HiPod · 个人项目｜Android 音乐播放器（AI 协作开发）**

- **主导需求与交互设计**：定义点击轮交互语义（转动/中键/MENU/全局播放键）、两段式音量（按中键进入调节态、松手退出，规避浏览列表误触）、专辑内按音轨号排序等细节，并给出可验收的判定标准。
- **主导技术选型与工程决策**：在 Expo Go 不可用（依赖原生模块）的前提下选定开发构建方案；把单主题重构为"调色板 + 预生成样式表"的双主题架构；用两个自写 config plugin 解决 `prebuild` 会抹掉原生改动的问题（media3 依赖去重、Gradle daemon JDK 21、固定签名注入）。
- **建立无设备验证方法并交付**：因机型禁用输入注入，建立"adb 深链跳转 + 控件树读取 + 逐帧像素差"的验收手段（跑马灯循环用帧差 933/0/7223 像素证明；用轮盘直径反推屏幕密度 2.977 px/dp，核对黑框实测 6.05dp 与配置一致），最终产出 51MB、脱离开发服务器可独立运行的 arm64 release 包。

## 三、STAR（面试口述版，挑一个讲）

**S｜背景**：想做一个 iPod Classic 交互的本地播放器，代码全部交给 AI 写。第一个卡点是**中文显示不是像素风** —— 拉丁字体 VT323 没有中文字形，系统会自动回退到默认字体，整个复古观感当场破功。

**T｜任务**：在不改设计方向的前提下，让中文也具备像素观感，并且要能长期复现（不能"这次手工搞一下"）。

**A｜行动**：
1. 先穷举可行路径并逐一验证：Google Fonts 无简体中文像素字体（CSS API 实测返回 400）；Fontsource 的「缝合像素」包只带 latin 子集；泛 CJK 包把字体按 unicode-range 拆成 1960 个 woff2，而 RN 既不支持 woff2 也无法按 unicode-range 回退。
2. 转向 GNU Unifont（OFL-1.1，全 CJK 点阵），但它的分发格式是 woff2 —— 于是用 npm 上的 `wawoff2` 转 TTF。
3. **不接受"应该能显示"**：自己写了一段 sfnt/cmap 解析（format 4/12）去校验码位覆盖，确认 57,087 个码位、抽样中文全部命中。
4. 把整条链路脚本化（`scripts/make-pixel-font.mjs`）并写进文档，换字体只需替换一个文件 + 改一行。

**R｜结果**：中文与拉丁统一为点阵观感，字体管线可一键复现；同一套"要证据、不接受推测"的方法后来还被用来解决材质贴图与图标抠图问题（例如发现 `react-native-svg` 15 在 Android 上未实现 `feTurbulence`，以及 `PIL.floodfill` 的 `thresh` 语义导致背景一个像素都没被清除，改用形态学重建式泛洪解决）。

## 五、面试高频追问 + 建议答法（诚实版）

**Q1：代码都是 AI 写的，那你贡献了什么？**
> 我负责"把事做对"的部分：需求拆解、技术选型、逐轮真机验收、发布。举个例子 —— AI 一开始给我的材质方案依赖 SVG 噪点滤镜，我没有直接接受，而是去查了本地依赖源码，发现 `react-native-svg` 在 Android 上根本没实现 `feTurbulence`，这个方案上线就是一片空白。我改成了程序化生成位图贴图。这类"AI 说没问题，但事实不是这样"的情况出现过很多次，判断和验证是我的工作。

**Q2：你怎么保证 AI 写的东西是对的？**
> 三个层次：纯逻辑用 Node 断言（`npm run verify`，它抓到过专辑排序把无音轨号的曲目排到最前的真实缺陷）；界面用真机截图核对；动画和尺寸这类"看起来对"的东西用像素级测量（帧差、密度换算）。我不会用"应该没问题"来收尾。

**Q3：这个项目你最大的收获是什么？**
> 学会了怎么把模糊需求变成可验收的改动，以及在 AI 给出结论时如何验证。真正难的不是让 AI 写代码，而是判断它写的东西在真实设备上是否成立。

**Q4：为什么不上架应用商店？**
> 这是个人项目，且 `iPod` 与点击轮造型是 Apple 的商标/设计标识，上架有合规风险，所以应用对外更名 HiPod、只做自签名分发。分发链路我做了固定签名密钥，保证已安装用户能覆盖升级。
